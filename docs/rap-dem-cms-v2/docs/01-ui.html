Thiết kế màn CMS và quy tắc giao diện

Cấu trúc

Sidebar: Tổng quan; Nội dung; Kinh doanh; Vận hành. Header có breadcrumb và danh tính nhân sự. Khu vực chính chứa tiêu đề, hành động, bộ lọc, bảng/form/chi tiết. Dữ liệu nháp tách trạng thái công khai. Thanh vàng chỉ dành cho prototype, không đưa vào sản phẩm thật.

Tra danh mục màn trong data/screens.json hoặc bảng Danh mục màn ở trang bàn giao. Mỗi dòng có mã UI, route, mã tính năng và mức tương tác thực tế. Các trạng thái không có dữ liệu / đang tải / lỗi / 403 / thành công có thể xem bằng bộ chọn chung. Đây là biến thể thiết kế, không phải lỗi API đã thực sự xảy ra.

Chi tiết hành vi chính

  • Kho phim: tìm/lọc; tạo nháp; slug duy nhất; metadata dùng chung. Nút gửi duyệt chỉ hợp lệ từ draft. Lưu thành công không làm đổi live revision.
  • Duyệt: gắn resourceRevision. Sửa sau khi gửi làm review cũ superseded. Reviewer thấy diff đúng hai snapshot; diff của prototype chỉ là ví dụ, DEV phải lấy snapshot thật.
  • Xuất bản: review approved + đúng revision + quyền nội dung + nguồn hợp lệ. Job accepted chưa phải live. Phim bộ có gate riêng. Scheduled là thời gian UTC được nhập từ múi giờ dự án.
  • Quảng cáo: lịch độc quyền không được thay bằng cột “trạng thái campaign”. Pause giữ reservation; cancel có lý do mới giải phóng.
  • Đối soát: import → validate → commit → lập kỳ → gửi duyệt → confirm → lock; tiền thực nhận ghi riêng. Tổng N/A khi chưa có nguồn, không dùng 0 thay thiếu dữ liệu.
  • Báo lỗi: new → triaged → in_progress → resolved → closed; resolved bắt buộc giải trình. Reopen có lý do.
  • Vai trò: UI ẩn/vô hiệu hóa hoặc hiển thị 403; API luôn kiểm quyền riêng. Không dùng localStorage.role làm auth.

Phần UI cần hoàn thiện khi nối backend

Form phụ (taxonomy, tài nguyên, creative, nguồn, nhân sự, trang thông tin, payment) minh họa cấu trúc, chưa bao phủ mọi widget/validation của schema. Bảng API và data dictionary là danh sách field yêu cầu; DEV phải hoàn thiện widget, lỗi field, permission field, trạng thái saving/pending và kiểm thử tích hợp. Danh mục màn ghi rõ phần nào là mô phỏng và phần nào chỉ xem thiết kế. Không coi ảnh là đặc tả backend đầy đủ.
